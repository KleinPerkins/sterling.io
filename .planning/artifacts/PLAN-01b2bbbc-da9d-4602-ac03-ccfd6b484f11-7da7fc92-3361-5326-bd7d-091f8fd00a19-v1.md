## First executable package: FND-01 — deterministic care replay

Purpose: turn existing in-memory reducer checks into bounded, portable, versioned scenarios that future behavior work can reproduce; repair the existing missing attention grace when Quiet or Focus ends. This is an independent S0/domain foundation package, not production S1.

- Primary requirement: R-044 / REQ-STERLING-044 (default-initial-state, same-version reproducibility subset, scenario X1; validated arbitrary initial snapshots and production reason traces remain S2). Supporting reducer regressions cover R-017/036/039 and affection/play/meal controls; they do not accept full C/D/E/J/K/X3/X4. Gesture ownership R-027 remains S1-CORE; bids remain S2-CARE, clocks/storage S2-STORE and privacy proof its native/manual audit.
- Owner: implementation lead (core/replay); independent technical reviewer for event validation and control precedence. Parent agent is sole worktree writer.
- Files: new `Sources/SterlingCore/SimulationReplay.swift`, existing `Simulation.swift` (including Codable/Equatable command conformance), new `Tests/SterlingCoreTests/ReplayTests.swift`, existing `SimulationTests.swift`. Stay within existing SwiftPM targets; no AppKit/SwiftUI/presentation or protected automation changes.
- Prerequisites: accepted PRD verified; current main/identity/writer guard; concrete documentation preview applied with fresh operation-bound consent. This package does not require a likeness, direct-touch, OS-support or production-UI decision. Applying draft documentation does not approve any such decision.
- Contract: Codable ordered synthetic inputs (command, bounded elapsed/contact quality, return), stable sequence starting at zero, seed and exact same-version replay identity. Reject incompatible schema/identity, duplicate/out-of-order sequence, nonfinite/out-of-range samples and excessive records/work before mutating a simulation. Return the final reducer state for deterministic equality and curve assertions. Recording is opt-in/test-owned; no live global event capture or persistent customer log is added.
- Scope limit: this is a developer fixture envelope, not the complete production event bus, save format, behavior scheduler, durable command deduplication or a promise of cross-platform bit-identical floating-point output. Input sequence is caller-supplied; the production runtime event arbiter is a later package.
- Grace correction: centralize the effective attention availability transition across all commands. Only false→true begins the existing 60-second prototype grace; remove unconditional Resume/Unpause refresh. Duplicate Quiet/Focus/Resume/Unpause and toggles while another restriction remains active must not restart or bypass it. Preserve the current tuning values as prototype proposals.
- Acceptance: round-trip a representative care replay; same input/seed/identity yields identical state including RNG; petting rises then ends and immediate re-entry retains satisfaction; play loses interest without resetting energy/boredom; hidden/paused samples do not advance needs; long return preserves familiarity/manual controls; malformed replay is rejected without executing a prefix; leaving Quiet/Focus cannot immediately start a bid; bounded size/time prevents an imported fixture from unbounded work.
- Verification: focused Swift tests, failing regression before grace fix, then full `make verify`; `git diff --check`; independent review; hosted `ci-required` on current PR head with every discovered Swift test on macOS 15 and 26. No physical acceptance is inferred.
- Evidence: source commit, Swift/Python counts, test names/coverage receipts, hosted run/check URLs, exact merge revision. Store only small sanitized observations; raw logs stay ignored.
- Risks: schema interpreted as long-term save compatibility; mitigated by explicit fixture-only naming/version identity. Proposed tuning becoming accepted; mitigated by unchanged values and status labels. Floating-point portability; compare within same build/content rather than assert universal identity.
- Rollback: revert this ordinary PR, rerun full verification; no persisted user save migration or settings change is introduced. Release remains manual.
